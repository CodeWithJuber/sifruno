# Disposable Linux runtime mechanics

This Windows host harness runs the **unactivated freeze-2** runtime test ELF and its independent review ELF in one new disposable AlmaLinux 9.8 x86_64 cloud-image overlay. The executables contain synthetic helpers. Passing them is evidence for the named filesystem, metadata, cancellation, namespace/ptrace/pidfd registration and descendant-cleanup tests only. It cannot qualify Apache/PHP-FPM serving, accounts, TLS, suspension, crash repair, service durability, distro support or cPanel compatibility. Production composition remains separate.

Use canonical `<primary>/lab/hostwebruntime-mechanics` or the assigned `<primary>/.worktrees/release-plan-sol/lab/hostwebruntime-mechanics` layout. During development, only the assigned worktree is used. Node and Python already installed on the Windows host are required. The explicit primary root is a **read-only** source of existing pinned tools, the original signed image and frozen worker/review inputs; output belongs to the checkout containing this runner. This harness never downloads or installs dependencies. It reuses the QEMU/CIDATA admission design from `scripts/alma-web-runtime.mjs` and the pinned pycdlib wheel from `scripts/alma-web-iso.py`; it never uses the adapted Apache/FPM qualification overlay.

```powershell
node lab/hostwebruntime-mechanics/run.mjs --primary-root '<primary>' --check-only
node --test lab/hostwebruntime-mechanics/test_admission.mjs
& "$env:LOCALAPPDATA/Programs/Python/Python312/python.exe" -I lab/hostwebruntime-mechanics/test_guest.py

# Builds a CIDATA ISO and new overlay; does not launch QEMU:

# Run only after root has reviewed the frozen sources and explicitly released launch:
node lab/hostwebruntime-mechanics/run.mjs --primary-root '<primary>' --run
```

`pins.json` fixes both manifests, both ELFs, fresh review overlay/report, historical provenance, the image verification record and tool inventory. Admission requires regular single-link inputs, no links/junctions, bounded sizes and exact hashes. It checks ten worker source files against their review copies, the fresh portable report's 43 source pins and overlay targets. The worker confirmed its ELF was compiled offline in place against base `12e4d3f`, without the review's canonical dependency overlay. `worker-dependencies.json` separately freezes its 25 local dependency/module inputs; raw source hashes remain separate. The runner also checks the 23 Go dependencies against canonical bytes after CRLF-to-LF normalization and records equality independently; newline encoding differences are not code differences. Its provenance distinguishes worker build confirmation from this harness's independent current-byte observations. Module manifests are pinned; this is not a complete compiler/module-cache attestation. The historical report's 42 identities are compared with the fresh set: only explicitly recorded runner/catalog portability changes may differ. Both old and recompiled review ELF hashes must be identical. The original runner bytes were not preserved, so its old hash is historical report provenance, not a claim that current runner bytes match it. Recorded absolute paths are translated to bounded logical identities; they grant no arbitrary script/ELF/root execution authority. A changed input is a closed admission failure. Hashes and past build reports establish provenance within the trusted workspace; they are not a reproducible-build or hostile-root attestation.

The checked-in catalog describes dated local freeze-2 inputs. A source ZIP **excludes** `.tools`, `.cache`, worktrees and review artifacts, so it does not contain these ELFs or historical reports and cannot run this dated catalog on its own. For another checkout, first obtain/admit the existing pinned offline tools/image through the repository tooling, then compile and independently review candidate/test sources in the fixed worker/review layout. Supply their frozen manifests, exact source report, overlay and ELF bytes in that layout and produce a new bounded `pins.json` source change for review. Its source paths, schema, test inventory, command vectors and tool/image pins must remain explicit; this runner exposes no arbitrary catalog/root-script/ELF execution flag. Do not label old hashes as new evidence or regenerate source identities merely to make admission pass.

All generated payloads, overlays, serial logs and reports remain under **this worktree** `.cache/hostwebruntime-mechanics/mechanics-<time>-<nonce>/`. Each invocation owns a fresh output directory. Preparation rechecks all inputs before generating the ISO; execution rechecks them before launch and after shutdown, plus the payload/ISO hashes. Source files and the original backing image are never written/deleted. Old output directories are retained for evidence. Reports contain relative identities; the original copied build report/overlay retain historical absolute provenance and stay local in the ignored cache.

QEMU uses software TCG, one CPU, 1536 MiB, no default devices, no NIC, no host shares, no display/monitor, a read-only CIDATA CD-ROM and only its owned writable overlay. Host child environments exclude credentials/provider keys. Windows launch uses hidden windows. Runtime is capped at ten minutes and serial capture at 2 MiB; failure/cancellation terminates only the QEMU child launched by this invocation. Serial write/short-write failures are caught in the event callback, recorded as `capture_error`, and trigger owned-child termination; they cannot escape past cleanup. Child errors retain the close/deadline wait. Fault-injection tests cover disk-full, short-write and size-limit handling. This is a trusted disposable test guest, not certification of QEMU as a hostile-guest sandbox.

Cloud-init runs a fixed root wrapper with serial redirection and an EXIT poweroff trap. It mounts CIDATA read-only/nosuid/nodev, copies the fixed payload and writes a nonce admission marker. `guest.py` invokes:

* Worker: `SIFRUNO_NATIVE_RUNTIME_TEST=1 worker.test -test.v -test.count=1 -test.timeout=90s`.
* Review: the same opt-in environment, `review.test -test.v -test.count=1 -test.timeout=40s -test.run '^TestReview'`.

Sixteen worker passes and fifteen review passes are mandatory. No opt-in/root/native test may skip. The single worker `TestNonLinuxUnavailable` skip is explicitly expected on Linux. Top-level RUN and result inventories, one final PASS, actual exits, output/deadline limits and ELF hashes must agree. Output is bounded to 512 KiB per ELF. The guest records OS/kernel/architecture, all UID/GID fields, groups, capabilities/seccomp, SELinux enforcement observation, boot ID and filesystem type/options/free space without changing policy. An unavailable required kernel mechanic fails the test; it is never replaced by a mock or a sysctl/SELinux relaxation.

Nonce-bound report markers must occur exactly once, in order, with one canonical JSON line (duplicate keys refused) and one exact zero-exit marker. Each test's raw output has its own nonce-bound block; the host recomputes its byte count, SHA and exact RUN/PASS/SKIP inventory independently from the guest summary. Missing, duplicated, echoed, truncated, skipped or failed evidence rejects qualification. Exact schema/command vectors and explicit `daemon_serving_qualified: false` are mandatory. The host report keeps separate QEMU, guest and test results. Windows parser/admission checks do **not** constitute Linux execution evidence. No VM has been run merely because this source or preparation passes its checks.

The first real boot, `mechanics-1791184127435-64ce21ac2e5b6cddf019e3d9`, failed before any Go test executed: QEMU reached its ten-minute limit after cloud-init selected `DataSourceNone`. The guest observed its DVD-ROM/sr0 and logged NoCloud retrieval failure. Read-back of that failed ISO showed all three NoCloud files had RockRidge `0o444` modes with no regular-file type bits, whereas the previously working installer ISO used `0o100444`. The failed ISO/report/serial remain preserved. The builder now uses `0o100444` and reads the completed ISO back, requiring all eleven names to be regular single-link files with that exact mode and original byte counts/hashes, plus CIDATA label and fixed NoCloud essentials. Four Windows ISO regression tests reproduce and reject the original defective mode. This fixes the demonstrated metadata defect; another reviewed native boot is required to establish causal closure and any Linux test result.
