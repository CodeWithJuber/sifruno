# phpMyAdmin's "Error: Token mismatch": cause, fix, and the fix on a real server, 2026-11-26
#
# Server: Linode 112009633 (g6-standard-2, de-fra-2), made by scripts/ci/nightly-fresh-install.sh with
# SIFRUNO_NIGHTLY_KEEP=1 and the owner's admin key added. AlmaLinux 9.8, SELinux Enforcing,
# openlitespeed-1.9.4-3.el9, lsphp83-8.3.37-1.el9, mariadb-server-10.11.18, phpMyAdmin 5.2.3 (the installer's
# pin). Deleted at the end (Part 7). The runner is the machine that ran Chrome 158 (agent-browser 0.45.0) over
# the internet; the Cloud Firewall admitted 8443 and 8444 from the runner only, 80 and 443 from anywhere.
#
# The cause. phpMyAdmin 5.2.2 and later name their cookies __Secure-NAME_https when the request is HTTPS
# (ChangeLog 5.2.2, issue #19141; libraries/classes/Config.php, getCookieName). Behind phpMyAdmin's origin
# every request is HTTPS (the proxy sets X-Forwarded-Proto: https), so phpMyAdmin's session cookie is
# __Secure-phpMyAdmin_https (Part 2). The proxy's allow list (1492930) passed SifrunoPhpMyAdminSignon,
# phpMyAdmin* and pma* only, so it dropped that cookie from every answer and every request. Each request
# then started a new phpMyAdmin session with a new token (Session::setUp), and the page's own AJAX POSTs,
# which carry the token of the session that drew the page, failed the check in Common::run with
# "Error: Token mismatch". Signing in still worked on every request, because the signon session cookie got
# through; that is why the database list and the tables showed. Log out failed the same way (LogoutController
# sends a mismatched POST back to the home page), and a SQL query from the SQL tab was refused.
# Ruled out on the way: the signon script and session names (the fix changes neither), a token in the
# redirect URL (the script redirects to /index.php with no query), the cookie path and SameSite (Path=/,
# SameSite=Strict, and every request is same-origin), and the first request being a POST (it is a GET; the
# failing requests are the page's later POSTs, Part 3).
#
# The fix: 7a1c740 "Pass phpMyAdmin its own session cookie over HTTPS (needs human review)": the allow list
# also takes __Secure-phpMyAdmin* and __Secure-pma*, and still no other name (not the panel's, not the
# admission cookie, no other __Secure- or __Host- name). 3a7c39d adds the same three checks to the dev-VM
# proof (proof.sh phpmyadmin), which passed before because it never looked at phpMyAdmin's first page.
#
# Releases: the branch head 203b3a4 (fresh install, Parts 1 to 3) and 7a1c740 (as an upgrade, Parts 4 to 6),
# each built with scripts/install/build-release.sh. Part 6's proof.sh builds its own panel from the checkout.
#
# Edits to the captured output: the server's address is written SERVER_IP (also in www.SERVER_IP.sslip.io),
# the temporary users' names end in <hex>, scratch paths are SCRATCH/, trailing spaces are removed. No cookie
# value, token, code or password is printed by the scripts; Chrome's HAR files stayed on the runner.
