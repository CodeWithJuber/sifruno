# Independent native executor challenges

This lab reviews a hash-frozen candidate of `internal/hostwebruntime`. Candidate files are copied into `testdata/candidate` only after the implementation owner freezes them. `testdata` keeps the candidate and challenge sources out of normal `go test ./...` package discovery. The runner compiles identical candidate bytes through a Go overlay at this existing lab directory (package name `hostwebruntime`); its imports use canonical account/compiler/coordinator sources. The lab location is necessary because Go vet/test subprocesses require a real working directory. It never creates or changes implementation files, canonical sources, Git, account state, or running services.

Run from a canonical checkout after the candidate manifest is present:

```powershell
powershell -NoProfile -File lab/hostwebruntime-review/run.ps1
```

The same runner also admits the exact assigned `.worktrees/native-web-review-sol/lab/hostwebruntime-review` location; from the primary checkout, use `powershell -NoProfile -File .worktrees/native-web-review-sol/lab/hostwebruntime-review/run.ps1`. Both layouts require bounded `module sifruno` admission and plain paths without reparse ancestors. Source dependencies come only from the canonical root; optional `-SourceRoot` must identify that exact root. Other worktree names and outside source roots are rejected. `-CheckLayout` checks admission without invoking Go or writing artifacts. `layout-challenge.ps1` exercises the exact runner functions against canonical and assigned-worktree fixtures, wrong modules/layouts, an outside source and a real Windows junction, then removes its owned fixture.

The runner uses the canonical `.tools/go/bin/go.exe`, offline existing `.cache/go-mod` inputs, and a lab-local build cache. Each run has a fresh `artifacts/<run ID>` directory containing exact commands, true exit codes, compiler/dependency/candidate/challenge pins, test output, and a JSON verdict. Schema2 reports identify input pins with portable `scope` (`lab`, `review`, or `canonical`) and relative `path`; the Go overlay retains actual local absolute paths needed by the toolchain. It restores its process environment. No dependency installation or native daemon activation is authorized by this command.

The common executable challenges require canonical recompile equality even for a structurally valid bundle whose hashes were recomputed after config alteration. They exercise generation/profile/snapshot drift, compiler path/mode admission, account ordering and revision admission, denied bootstrap identity, root containment, exposure refusal, and copied caller byte isolation. Windows challenges require every native activation/observation path to return unavailable without creating state. These are actual pure admission and Windows rejection checks, not simulated Apache/PHP-FPM success.

Linux compilation and vet are recorded separately and do not execute the Linux test binary. Any Linux lifecycle helper tests must be explicitly identified as helper evidence. Actual Apache/PHP-FPM qualification requires a disposable provisioned Linux guest and separate observation of owned listeners, foreign/known Host denial, static/PHP serving, tenant UID/GID/groups/chroot/capabilities, and cleanup. Existing `lab/web_runtime_fixture.py` observations qualify only the exact binaries/profile used in their original run; they do not qualify this new executor.

Native review acceptance requires safe immutable configuration containment, no symlink/hardlink or permission substitution, full file hashes and deterministic inventory, durable pending/corruption refusal, independent process and listener identity, and exact known-state CAS/rollback. Stop/reap must use owned process lifetime evidence and refuse foreign/reused identities. The proposed ptrace-stopped PID-namespace-init registration gate must durably record pins before detaching; cancellation and crash before registration must not let an unregistered daemon serve. Namespace/pidfd/ptrace authority, restart adoption, concurrent external root changes, and cancellation/reaping remain unqualified until corresponding executable and guest evidence is produced.
